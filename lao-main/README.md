## About Laravel

Laravel is a web application framework with expressive, elegant syntax. We believe development must be an enjoyable and creative experience to be truly fulfilling. Laravel takes the pain out of development by easing common tasks used in many web projects, such as:

- [Simple, fast routing engine](https://laravel.com/docs/routing).
- [Powerful dependency injection container](https://laravel.com/docs/container).
- Multiple back-ends for [session](https://laravel.com/docs/session) and [cache](https://laravel.com/docs/cache) storage.
- Expressive, intuitive [database ORM](https://laravel.com/docs/eloquent).
- Database agnostic [schema migrations](https://laravel.com/docs/migrations).
- [Robust background job processing](https://laravel.com/docs/queues).
- [Real-time event broadcasting](https://laravel.com/docs/broadcasting).

Laravel is accessible, powerful, and provides tools required for large, robust applications.

## Booking confirmation email

When an admin changes a booking to **Confirmed**, CasaLao emails the booking owner. To deliver messages through Gmail, enable 2-Step Verification on the sending Google account and create a Google App Password. Set these values in your local `.env` file:

```dotenv
MAIL_MAILER=smtp
MAIL_SCHEME=smtp
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=your-gmail@gmail.com
MAIL_PASSWORD=your-google-app-password
MAIL_FROM_ADDRESS=your-gmail@gmail.com
```

Keep the App Password private and do not commit it. Then run `php artisan config:clear`. With `MAIL_MAILER=log`, emails are written to the Laravel log instead of being delivered to Gmail.

If sending fails, the booking remains confirmed and the bookings page shows a warning. After fixing the SMTP settings, select **Confirmed** again and click **Update status** to retry the email.

To notify additional inboxes only when an admin confirms or cancels a booking, set `BOOKING_NOTIFICATION_EMAILS` in `.env` to a comma-separated list of email addresses. No notification is sent when a user first creates a booking.

The booking owner also receives an email when an admin confirms or cancels their booking.
If delivery fails, the admin can select the same status again to retry; successful status notifications are not sent again.
